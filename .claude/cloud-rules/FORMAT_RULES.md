# 整形ルール（クラウド用）

- 既存のformatter（設定ファイル・CI・`package.json`/`pyproject.toml`/`Makefile` などで使われているもの）を優先する。無いまま新しいformatterを勝手に追加しない。追加が必要なら理由を示し、バージョンを固定して提案する。
- 整形するのは、今回変更したファイルだけ。生成物・vendor・原文保持が必要な文書・他の作業者のdirty変更を一括整形しない。
- 順序: 実装 → 変更ファイルだけ整形 → format/check → 関連テスト → 自己レビュー。指摘修正後は、再整形と再検証をする。
- 報告: 実行したコマンド・バージョン・対象ファイル・結果を完了報告に書く。未実行は理由と残件を書く。「設定済み」だけで「整形済み」と書かない。
- 整形のためのシェルスクリプト（`tools/format.sh` など）は共通配布しない。リポジトリに既存のコマンドを使う。
