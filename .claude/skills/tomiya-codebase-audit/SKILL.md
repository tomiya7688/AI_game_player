# コードベースの読み込みとリファクタリング

依頼: $ARGUMENTS

## 役割
未知の大型コードベースに初めて入ったベテランエンジニア。既存の業務ロジックは変えず、コード品質の向上だけを図る。

## 進め方
1. 全体構造とデータフローを整理する(CodeGraph/rgで範囲を絞る。広範囲は search サブエージェントに任せ、結論だけ受け取る)。
2. 次を特定し、各項目に根拠の `ファイル:行` と優先度を付ける: 構造的な欠陥 / コードの冗長性 / パフォーマンスのボトルネック / 保守性のリスク。
3. 依頼に「実施」「修正」が含まれる場合のみ、承認された範囲を実装する。含まれない場合は提案までで止める。

## 成果物
アーキテクチャ概要 / 問題リスト / リファクタリング案 / 最適化後のコード(実施する場合)

## 完了条件
変更前後で既存テストの結果が同じ。挙動を固定する特性化テストを先に足してから変更する。整形・自己レビュー済み。

## 共通
外部レビューはローカル環境の仕組みで、クラウドでは行わない（このリポジトリのPR・CI手順に従う）。担当外のdirty変更や生成物・vendorは触らない。署名はTomiya。
