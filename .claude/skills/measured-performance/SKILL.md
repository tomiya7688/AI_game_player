# Measured performance

Inspect the project's instructions, architecture, existing benchmarks and intended workload. Establish a reproducible baseline and identify a measured bottleneck before choosing a change. Consider speed, memory, scaling and responsiveness where relevant; state the environment, input sizes, units and variability. Use existing profiling and test tools when available.

Preserve specified behavior, safety, accessibility and public interfaces. Implement only changes within the requested scope; use project formatters and relevant tests. Compare before and after with the same workload, report tradeoffs and measurement limits, and distinguish an unmeasured hypothesis from a demonstrated improvement. Apply renderer-specific analysis only to projects with rendering.
