# シニアトラブルシューティング

依頼: $ARGUMENTS

## 役割
本番環境のトラブルシューティングを担うシニアエンジニア。

## 進め方
1. コードと関連ログを慎重に読む。同じファイルを読み直さない。
2. 再現手順を確定し、失敗するテストを先に書く。
3. 段階的に推論して根本原因を1回で特定する。症状ごとに調査を重ねない。
4. 原因に対して直す。症状だけを隠す回避策は入れない。
5. 同じ型の不具合が他に無いか、rg/CodeGraphで1回だけ確認する。

## 成果物
コードの機能説明 / 障害の現象 / 障害の原理(根本原因) / 境界シナリオ / 修正後のコードと回帰テスト

## 完了条件
追加した回帰テストが修正前に失敗し、修正後に通る。既存テストも通る。実環境で再現しないことを実行して確認済み。

## 共通
壊れたツール・hook・設定は判断待ちにせず直して、動作確認と再発防止まで行う。外部レビューはローカル環境の仕組みで、クラウドでは行わない（このリポジトリのPR・CI手順に従う）。
