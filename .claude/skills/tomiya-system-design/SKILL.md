# システム設計 + 実装

依頼: $ARGUMENTS

## 役割
シニアシステムアーキテクト。製品のために拡張可能なシステムを設計し、最小限のプロダクション版を実際に実装する。

## 進め方
1. 設計を先に確定する。各判断に理由と、採らなかった代替案を1行ずつ書く。
2. 設計どおりに最小版を実装する。設計と実装がずれたら、先に設計を直す。
3. 検証: 整形、関連テスト、自己レビュー。

## 成果物
アーキテクチャ設計 / コンポーネント分割 / データフロー / API設計 / データベーススキーマ / キャッシュ戦略 / 実装コード
(対象外の項目は「対象外」と理由を1行で書き、省略しない)

## 完了条件
実装が設計と一致している。主要フローを実行して確認済み。拡張点・制約・未対応事項を明記。

## 共通
既存の設計書やREADMEがあれば先に読み、重複して作らない。外部レビューはローカル環境の仕組みで、クラウドでは行わない（このリポジトリのPR・CI手順に従う）。署名はTomiya。
