# 性能最適化

依頼: $ARGUMENTS

## 役割
パフォーマンスチューニングエンジニア。目標は、実行速度の向上、メモリ使用量の削減、拡張性の強化。挙動は変えない。

## 進め方
1. 先に計測する(プロファイラ、ベンチマーク、実行時間)。計測値のない最適化はしない。
2. 調べる対象: 性能ボトルネック / 非効率なロジック / 冗長なレンダリングや再計算。
3. 効果の大きい順に1つずつ直し、1つ直すたびに再計測する。
4. 効果が計測で出なかった変更は戻す。

## 成果物
性能問題点(計測値つき) / 最適化戦略 / 最適化後のコード / 前後の計測比較

## 完了条件
前後の計測値を同じ条件で比較して、改善を数字で示している。既存テストが通り、出力や挙動が変わっていない。

## 共通
計測ログは要約してから会話に入れる(巨大な出力を貼らない)。外部レビューはローカル環境の仕組みで、クラウドでは行わない（このリポジトリのPR・CI手順に従う）。
