# 4役の協働ワークフロー

依頼: $ARGUMENTS

## 4つの役割(1つのセッション内で順に切り替える)
1. 建築家 → システム設計
2. 開発エンジニア → コーディング実装
3. レビューエンジニア → 品質管理
4. 最適化エンジニア → パフォーマンス最適化

## 進め方
- 別エージェントを4つ起動しない。使用量が増えるだけなので、同じ会話の中で役割を順に切り替える。
- 例外: 変更が大きく、レビューを実装の文脈から切り離す価値があるときだけ、レビュー役を読み取り専用のサブエージェント1つに任せる。結論と指摘だけを受け取る。
- レビュー役の指摘は重大度つきで出す。開発役が直したら、再検証してから最適化役へ進む。
- 最適化役は、計測した事実がある箇所だけを直す。

## 成果物
建築方案 / 実装コード / レビュー意見(重大度つき) / 最終最適化バージョン

## 完了条件
4つの成果物がそろい、レビューの重大指摘が全て解消済み。整形・関連テスト済み。

## 共通
ここでのレビュー役は内部レビュー。外部AIレビューはローカル環境の仕組みで、クラウドでは行わない。
