# クラウドのレビュー手順（PR前→PR後）

ローカルの複数AIレビュー起動口・共有キューはクラウドに無い。次の3段で行い、結果を証跡表にまとめる。依頼対象: $ARGUMENTS（無ければ今回の差分全体）。

1. **PR前（自己点検）**: 整形・関連テスト・`python3 tools/check_docs.py docs` と `python3 tools/check_links.py AGENTS.md docs/README.md`（存在するファイルだけ）を通す。通らない指摘は直す。
2. **PR前（レビュー）**: 組み込みの `/code-review` を実行する。続けて agent `code-reviewer` に、差分（`git diff <base>...HEAD`）と直接の根拠だけを渡して1回レビューさせる。秘密・個人情報・ローカル絶対パスを渡さない。有効な指摘は直して再度テストする。同じ指摘への再レビューは1回まで。
3. **PR後**: PRを作成・更新した後に CodeRabbit の結果（コメント・チェック）を確認する。未着なら10分を目安に打ち切り「未着」と記録する。有効な指摘は直す。GitHub Copilot へのレビュー依頼は停止方針のため行わない。

## 証跡表（PRコメントに書く）

| 項目 | 実施日時(UTC) | 対象HEADのSHA | 結果 | 備考 |
| --- | --- | --- | --- | --- |
| /code-review | | | 実施/省略 | 指摘数・対応 |
| code-reviewer | | | 実施/省略 | 指摘数・対応 |
| CodeRabbit | | | 確認済/未着 | 指摘数・対応 |
| Copilot | - | - | 依頼しない（停止方針） | - |

- 省略する場合は理由を1行書く（枠切れ・未応答・利用不可など）。省略を成功扱いにしない。
- 証跡が無い項目は「未実施」と報告し、「レビュー済み」と書かない。
- 必須CI・承認条件は迂回しない。無料枠外・課金が要る経路へは送らない。
