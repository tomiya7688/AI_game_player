# 作業の開始・完了チェック

依頼対象: $ARGUMENTS（無ければ今回の作業全体）。

## 開始時

1. `git status` と `git worktree list` を確認する。他のworktree・ブランチが同じファイルを変更していないか `git log --oneline -5 -- <対象>` で見る。必要なら取り込む（他者の未コミット変更を捨てる操作は確認する）。
2. `AGENTS.md`・`CLAUDE.md` から設計書の目次（`docs/README.md` など）を開き、変更対象の設計書を見つける。
3. 整形・テスト・ビルドのコマンドを、`README`・`AGENTS.md`・CI設定から確認する。

## 完了報告前

1. **設計書**: 設計に影響する変更は、同じ作業で設計書を更新し最終確認日を直す。`python3 tools/check_docs.py docs` を通す（`tools/` が無い場合は報告する）。
2. **リンク**: `python3 tools/check_links.py AGENTS.md docs/README.md`（存在するファイルだけ指定）でリンク切れが無いことを確認する。
3. **整形**: `.claude/cloud-rules/FORMAT_RULES.md` に従い、今回変更したファイルだけを整形し、コマンドと結果を報告する。
4. **テスト**: 関連テストを実行し、実行したコマンドと結果を報告する。未実行は理由を書く。
5. **レビュー**: PRにする場合は skill `cloud-review` を実行する。
6. **個人情報・秘密**: `git diff` を見て、メールアドレス・氏名・認証情報・ローカル絶対パス（Windowsのユーザーフォルダ配下、Eドライブ配下など）が含まれないことを確認する。含まれていたら除いてから報告する。
7. 自分が起動したバックグラウンドプロセスが残っていないことを確認する。
8. 文脈が約150kを超えたら `.claude/cloud-rules/HANDOFF.md` に従って引き継ぐ。

報告には、更新した設計書、実行したコマンドと結果、未確認事項を書く。
