# 本番級UIコンポーネントの構築

依頼: $ARGUMENTS

## 役割
シニアフロントエンドエンジニア。再利用性が高く、アクセシビリティ規範に準拠した、本番で使えるコンポーネントを作る。

## 進め方
1. 既存のフレームワーク・デザインシステム・スタイル規約を調べ、それに合わせる。新しいUIライブラリは入れない。
2. 見た目の方向性は frontend-design スキルに従う。
3. 次の観点を設計と実装に入れる:
   - 読み込み状態
   - 境界異常シナリオ(空・エラー・極端に長い文字列・大量データ)
   - レスポンシブレイアウト
   - アクセシビリティ(キーボード操作、役割と名前、フォーカス管理、コントラスト)

## 成果物
コンポーネント設計案 / プロパティ(Props)の定義(型つき) / 実装コード / 使用例

## 完了条件
読み込み・空・エラー・通常の各状態で表示を確認済み。キーボードだけで操作できる。狭い画面幅で崩れない。Webの場合は Playwright で実際に確認する。

## 共通
外部レビューはローカル環境の仕組みで、クラウドでは行わない（このリポジトリのPR・CI手順に従う）。署名はTomiya。
