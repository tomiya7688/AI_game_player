# 学習診断（Training Value / Error Diagnosis）機能説明書

[リポジトリに戻る](../README.md) ｜ [学習用データの説明](学習データセット生成機能説明書.md) ｜ [記録と学習の案内](guide/records_learning.md)

Issue #169（親 #36）の実装範囲を説明します。Experienceに記録された操作効果から、学習対象としての価値（training value）と、誤りや低価値の原因候補になるcomponentを決定論的に選びます。モデルの更新（#170）、採否・rollback（#171）、Champion/Challengerの比較評価（#173）は行いません。

## 何を入力し、何を出力するか

| 項目 | 内容 |
| --- | --- |
| 入力 | `ExperienceEpisode`群。各stepの`knowledge.action_outcome` event（既存`KnowledgeUpdateSample`で検証）と、任意の`learning.diagnosis_context` event |
| 出力 | `TrainingDiagnosisReport`（`schema_version=1`）。case単位の`CaseDiagnosis`と、component×Knowledge scope単位の`ComponentTarget` |
| 入口 | `training_diagnosis.diagnose_episodes(episodes, policy)`、またはcaseを直接渡す`diagnose_cases(cases, policy)` |
| 副作用 | なし。ファイル・DB・モデル・保持（retention）索引へ書き込みません |

`learning.diagnosis_context`のpayloadは、次の6 fieldだけを持ちます。同じstepの`outcome_event_id`で操作効果eventに結び付けます。

| field | 意味 |
| --- | --- |
| `outcome_event_id` | 対応する`knowledge.action_outcome`のevent ID |
| `label_status` | #647の`causal_status`を小文字にした確定度（下表） |
| `recognition_reliability` | 認識の校正値（0..1、任意）。操作効果eventの`candidate_reliability`と両方あれば小さい方を使う |
| `decision_expected_success` | 判断時に予測した成功率（0..1、任意） |
| `outcome_conflict` / `outcome_abstained` | Outcome検出器（`OutcomeEvent.conflict`/`abstained`）の矛盾・保留 |

## 確定度の扱い（#647との境界）

確定ラベルとして扱うのは`verified_effect`だけです。他の段階は不確実な根拠として、確信度に上限を付けて残します。

| 確定度 | 由来 | 帰属の扱い |
| --- | --- | --- |
| `verified_effect` | `verified=True`かつ`evidence_kind`と出所が一致する決定論検証（`deterministic_action_effect`）または人手訂正（`human_correction`） | `strict=True`の帰属になり得る |
| `supported_effect` | `calibrated_action_effect`。#647で独立校正の受入が済むまで確定ラベルにしない | 不確実（上限0.5） |
| `expected_consistent` / `observed_only` | 予測一致だけ、または観測だけ | 不確実（上限0.5） |
| `conflict` / `unknown` | 根拠の矛盾、または根拠なし | 不確実（上限0.5） |

- 文脈eventの`label_status`は、操作効果eventから求めた確定度より**弱める方向にだけ**作用します。文脈eventで確定へ格上げすることはできません。
- #647の厳格gateが実装された後は、そのAssessmentを文脈eventの`label_status`として渡す想定です。gateの判定そのものは本機能に含みません。
- 不確実な根拠からの候補は`hypothesis`として出力し、#712のsoft学習経路が仮説として利用できる形に残します。確定した正解ラベルとしては扱いません。
- #689の「検証済み効果だけをLight更新へ渡す」経路とは別の読取専用の診断で、Light更新の入力・Journalの記録には影響しません。

## 帰属の規則（規則版1）

| 条件 | component | failure_kind | 根拠（basis） |
| --- | --- | --- | --- |
| `before_dispatch_failure` | execution | `execution_failure` | receiptの事実。`strict=True`、確信度0.9 |
| `dispatch_unknown` | execution | `execution_unconfirmed` | 入力が届いたか不明。`strict=False`。効果をrecognition/decisionへ帰属しない |
| 検出器の矛盾、または確定度`conflict` | outcome_interpretation | `outcome_conflict` | `outcome_disagreement`。`strict=False` |
| 効果`unknown`、または検出器の保留 | outcome_interpretation | `outcome_unresolved` | 保留0.3、単なる未知0.1 |
| failure/no_effectで認識信頼度が`low_reliability`（0.5）未満 | recognition | `recognition_unreliable` | 確定度に従う |
| failure/no_effectで予測成功率が`overconfident_expectation`（0.7）以上 | decision | `decision_overconfident` | 確定度に従う。認識信頼度が低いほど弱める |
| failure/no_effect（上記以外） | decision | `action_ineffective` | 同上 |
| successで予測成功率が`underestimated_expectation`（0.3）以下 | decision | `decision_underestimated` | 確定度に従う |

- 効果の強さはfailure=1.0、no_effect=0.7です。確定度ごとの倍率（verified 1.0 / supported 0.6 / expected_consistent 0.35 / observed_only 0.25 / conflict 0.5 / unknown 0.15）と効果の確信度を掛けます。
- caseの`training_value`は、帰属確信度を`1 - Π(1 - c)`で結合した0..1の値です。帰属がないcase（例：予測どおりの成功）は0で、`findings`に含めません。
- `ComponentTarget`は`strict_support`（確定根拠数）が`minimum_strict_support`（既定2）以上なら`candidate`で、確信度は確定根拠だけから結合します。2件未満は`hypothesis`で、全根拠を結合した値を上限0.5に抑えます。#170はcandidateを更新提案の対象、hypothesisを追加観測の対象として扱う想定です。
- `evidence_refs`は確定根拠を優先した確信度上位の`DatasetSource`（episode/step/event）参照です。#171/#173の対象failure集合・regression比較の参照として使えます。

## 保持価値（storage value）との分離

`training_value`は「学習の対象にする価値」で、#164のretention（Protected・TTL・容量予算）が扱う「保存し続ける価値」とは別の値です。診断はartifactの容量・機密flag・保持状態を読まず、retention索引へ書き込みません。同じ効果を持つcaseは、artifactの有無にかかわらず同じ`training_value`になります（`test_training_value_is_independent_of_storage_properties`）。

## 除外と上限

| 除外理由 | 条件 |
| --- | --- |
| `not_executed` | `dry_run`/`planned`/`cancelled`。実送信がない操作は帰属しない |
| `invalid_outcome_event` | 既存`KnowledgeUpdateSample`の契約に合わない操作効果event |
| `invalid_context` | 文脈eventのfield・値が不正、または同じ効果eventに複数の文脈がある（どれも採用しない） |
| `orphan_context` | 同じstepに対応する操作効果eventがない文脈event |
| `duplicate_reference` | 同じepisode/step/event参照の重複 |
| `case_limit` | `max_cases`（既定4096）を超えたcase |

出力は`max_findings`（256）、`max_targets`（64）、`max_evidence_refs`（16）で切り詰め、切り詰めた場合は`findings_truncated`/`targets_truncated`をTrueにします。

## 再現性と版

- episodeはID順、stepは順序番号順に処理し、入力の順序が変わっても同じ報告になります。
- `policy_fingerprint`は規則版と全policy値のSHA-256先頭16桁です。`to_dict()`の`diagnosis_id`は報告内容全体のSHA-256です。
- 出力契約は`schema: "training-diagnosis"`、`schema_version: 1`です。規則やfieldを変えるときは版を上げます。

## 未実装・制限

- `learning.diagnosis_context`を記録する本番の生成経路（Decision/Outcomeの記録側）は未接続です。現在の本番Experienceでは`knowledge.action_outcome`だけから診断し、判断時予測・検出器の矛盾がないcaseはdecisionの`action_ineffective`かoutcome_interpretationの未解決として扱います。
- 規則ベースの帰属で、学習済みの原因推定器や因果推論は使いません。確信度は根拠の強さの目安で、原因の正しさを保証しません。
- 更新提案の生成は[Challenger更新機能説明書](Challenger更新機能説明書.md)（#170）がこの報告を入力にします。評価（#173）、採否・rollback（#171）、#647の厳格gate本体は別Issueです。
