# 操作候補統合

この説明書は、画面取得後にGUIがAutomation・OCR・画像候補を統合し、候補の入力元と安全評価を表示する仕組みを実装者へ説明する。

画面を取得すると、`Application.capture_screen()` はObservationを画面JSON欄へ保存し、空配列 `[]` を含むAutomation候補JSONとObservation内の `ocr_candidates` / `image_candidates` を `ApplicationWorkflowService.preview_observation()` へ渡す。previewは候補と評価結果を返しますが、実行中のPipelineが読む `MemorySource` は変更しません。利用者はAutomation候補JSONを編集しなくても画面候補を確認でき、表示確認だけで実行中stepの入力を差し替えません。

`CandidateMerger.merge_with_sources()` は各候補を統合し、代表候補と候補に寄与した入力元を返す。優先順位は Automation > OCR > image とし、同じ入力元内ではconfidenceが高い候補を残す。重複判定は同一ID、矩形IoU、近接座標と正規化済み文字列を使う。OCR候補と画像候補が同じ画面要素を示す場合、評価欄には両方の入力元を表示する。

`ApplicationWorkflowService.update_observation()` はstep開始時に統合候補を `ActionEvaluator` で評価し、候補ID・許可状態・拒否理由・入力元を含む結果を返す。評価が成功した後にだけ、同じObservationと統合候補を `MemorySource` へ登録する。画面取得後のpreviewはこの登録を行いません。confidence `0.0` の画像候補は低信頼度として拒否され、AI判断や実行へ渡りません。

`DetectedElement` は `bbox / source / confidence / text / element_type` を保持する。認識器固有の出力形式はこの中間表現で受け、操作候補へ変換してから統合する。
