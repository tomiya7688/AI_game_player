コマンド指向 技術規定書（草案 v0.1）

目的

コマンド指向とは、アプリケーション全体を「コマンド（要求）」を中心として設計するプログラミングパラダイムである。

本規定では、コマンドを主体とし、責務単位の状態マシン（Machine）によってシステムを構築する。


---

基本理念

コマンド指向では

コマンドが主体（Master）

である。

コマンドは各Machineへ送信され、

Machineは状態を変化させたり結果を返したりする。

Machineは自ら他Machineへ命令を送る必要はない。


---

Machine

Machineは責務単位の状態マシンである。

Machineは以下を持つ。

・状態(State)

・コマンド(Command)

・Parser

・Executor

・出力(Output)

・必要に応じて子Machine

Machineは物理的なオブジェクトではなく、

機能単位である。

例

画面Machine

保存Machine

通信Machine

Renderer Compute

など。


---

コマンド

コマンドはMachineへの要求である。

例

ShowWindow

SaveFile

SendPacket

DrawFrame

Machineはコマンドを解釈し、

状態変化または出力を行う。


---

Parser

ParserはコマンドをMachine内部命令へ変換する。

入力方法は自由である。

例

GUI

JSON

CSV

CLI

API

Excel

音声入力

など。

入力インターフェースは複数存在してよい。

Parserによって共通コマンドへ変換される。


---

Executor

ExecutorはMachine内部命令を実行する。

ExecutorはMachine固有である。

Machine外部から直接操作してはならない。


---

State

Machineは必ず状態を持つ。

例

画面Machine

表示中

非表示

ロード中

Renderer

初期化済

描画中

終了

Machineはコマンドによって状態遷移する。


---

Machine分割

Machineは責務が大きくなった場合のみ分割する。

例

画面Machine

↓

画面入力Machine

画面表示Machine

画面処理Machine

Machine分割は責務単位で行う。

速度改善のみを目的とした分割は推奨しない。


---

Compute Machine

高速演算を目的としたMachine。

例

Renderer

Physics

FFT

AI推論

画像処理

数値計算

Compute Machineは

Parserや状態遷移を最小限にする。

高速性を最優先とする。


---

Machine通信

Machine同士はコマンドによって通信する。

Machine内部状態へ直接アクセスしてはならない。

通信は

Command

Event

Result

で行う。
---

データ

データはMachine外部に保存する。

例

JSON

CSV

Database

Machineはデータ所有者ではなく、

状態管理者である。


---

入力インターフェース

入力方法は自由である。

GUI

JSON

CSV

Excel

CLI

API

Automation

など。

重要なのは

共通コマンドへ変換されること

である。


---

コマンド所有権

コマンド指向では

コマンドが制御権を持つ。

Machineはコマンドを受信して動作する。

一般的な

object.method()

とは考え方が異なる。


---

オブジェクト

Machineは状態マシンである。

一般的なクラスインスタンスとは異なる。

Machineは

Parser

Executor

State

Command

を持つ。


---

設計原則

一つのMachineは一つの責務を持つ。

Machineは責務で分割する。

速度が必要な計算はCompute Machineへ集約する。

入力方法は自由。

コマンドのみを共通化する。

状態はMachineのみが変更する。


---

開発指針

GUIはコマンド生成器である。

JSONはデータ保存形式である。

CSVは交換形式である。

Machineはこれらを意識しない。

---

設計思想

コマンド指向では、システムは「責務を持つ計算作業者（Machine）」の集合として構築される。各Machineは独自のコマンド体系・Parser・Executor・状態を持つ小さな実行環境であり、コマンドを受けて自身の責務を遂行する。

Machineの目的は巨大な問題を直接解決することではない。自らの責務に応じて問題を適切な単位へ分割・変換し、必要に応じて結果を返すことである。

速度が要求される計算は責務単位でCompute Machineへ集約し、変更頻度の高い業務ロジックやUIは通常のMachineとして実装する。

コマンド指向は「柔軟性・変更容易性・責務分離」を最優先とし、入力インターフェースに依存しない共通コマンドを中心にシステム全体を設計することを目的とする。
