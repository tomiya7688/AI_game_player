# 評価指標

`MetricsCalculator` は実行履歴から総数、dry-run数、実行成功数、失敗数、操作別回数を集計する。GUI品質評価では、この集計を迷い時間・同一画面表示回数などの指標へ拡張する。

## 汎用評価プリミティブ

`PrimitiveEvaluator` は `OutcomeAssessment` とゲーム非依存の正規化signalから、以下の6軸を決定論的に生成する。

- `progress`
- `survival`
- `resources`
- `novelty`
- `repetition`
- `irreversible_loss`

各軸は `EvaluationAxis(value, confidence, evidence)` として値・confidence・根拠を分離して保持する。`repetition` と `irreversible_loss` はペナルティ軸として負値へ変換される。Core単体の既存helperはterminal Outcomeをprogress/survivalへ写し、ongoingのsurvival既定値も持つ。本番Runtimeでは、その既定値を観測事実にせずavailability=False/value=0/confidence=0へ抑制する。

`EvaluationResult` は6軸、適用weight、正規化済み最終score、score confidenceを保持する。weightはEvaluator既定値に加えて評価呼び出し単位で上書きできる。本番は #491 の `RuntimeEvaluationAdapter` と明示的なgame/scene/goal profileを使い、前実操作と候補hypotheticalを分けてContext/Traceへ渡す。`to_decision_context()` はCore単体のcompact helperであり、本番の可用性・scope・送信許可を代替しない。

`EvaluationLog` はCore単体の追記helper。本番は既存Session Trace/Event Journalへ6軸、元/現在profile、版、出所、最終Decisionを記録し、欠損coverageを含むconfidence-weighted MCDAをBaselineのsoft順位へ反映する。Outcome検出自体は `OutcomeEvaluator` / Issue #34 の責務で、AdapterはModelの自己申告やpixel変化だけを意味的な進捗へ変えない。confidenceは校正済み成功確率ではない。

source信頼、Model送信opt-in、単位/scale・欠損・性能計測と未達条件は[Runtime Evaluation](architecture/runtime_evaluation.md)を参照する。
