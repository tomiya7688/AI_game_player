# 評価指標

`MetricsCalculator` は実行履歴から総数、dry-run数、実行成功数、失敗数、操作別回数を集計する。GUI品質評価では、この集計を迷い時間・同一画面表示回数などの指標へ拡張する。

## 汎用評価プリミティブ

`PrimitiveEvaluator` は `OutcomeAssessment` とゲーム非依存の正規化signalから、以下の6軸を決定論的に生成する。

- `progress`
- `survival`
- `resources`
- `novelty`
- `repetition`
- `irreversible_loss`

各軸は `EvaluationAxis(value, confidence, evidence)` として値・confidence・根拠を分離して保持する。`repetition` と `irreversible_loss` はペナルティ軸として負値へ変換される。signalが無い軸は推測せず0値・0 confidenceを基本とし、terminal outcomeから機械的に判断できるprogress/survivalだけをOutcomeから補う。

`EvaluationResult` は6軸、適用weight、正規化済み最終score、score confidenceを保持する。weightはEvaluator既定値に加えて評価呼び出し単位で上書きでき、game / scene / phase profileを後から接続できる。`to_decision_context()` は小型Decision LLMへ渡すためのcompact JSONを生成する。

`EvaluationLog` は各軸・confidence・weight・最終scoreをJSONへ追記し、Action ID等のmetadataと共に評価過程を追跡できる。Outcome検出自体は `OutcomeEvaluator` / Issue #34 の責務であり、PrimitiveEvaluatorは検出済みOutcomeとgeneric state signalの価値変換だけを担当する。
