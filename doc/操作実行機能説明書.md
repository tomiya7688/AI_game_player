# 操作実行

`ActionExecutor` は安全評価済み候補の実行境界を提供する。既定は `dry_run=True` で、選択結果だけを返してOS入力を行わない。実入力は別Executorとして明示実装し、誤って有効化されないよう未実装時はエラーにする。

実入力を開始する前に対象ウィンドウが選択されていることを確認し、WindowsではHWNDが有効かを再検証する。`window_message` はクリック／キー入力を選択中のHWNDへ送り、カーソル移動やグローバルマウス入力へフォールバックしない。対象が未選択または失効していれば、設定保存や判断・実行を開始せずエラーにする。

利用者が実行中に停止を要求すると、`RunController`は現在の実行世代を無効にする。`DecisionPipeline`はその停止状態と実行世代を`ActionExecutor`へ渡し、Windows入力のキー保持または待機を中断させる。キー保持の中断時、`WindowsInputExecutor`は押下中のキーを解除してからstepを終了する。停止後にOllamaの推論応答が返っても、その古い応答は新たな実入力へ進まない。

Windowsの連続実行はF12と手動カーソル移動を停止要求として扱う。`mouse`方式はクリック前に`SetCursorPos`でシステムカーソルを移動するため、`WindowsInputExecutor`は移動予定座標とAPI呼び出し中・完了の状態を`Application`へ通知する。`Application`は通知されたクリック先への移動を手動操作と区別し、自動移動先として通知されていない座標への移動で連続実行を停止する。`window_message`方式はカーソルを移動しない。

画面取得のたびに`Application`は非同期の状態評価workerを起動する。複数の評価が重なった場合、最後に起動した評価workerの結果だけを`previous_observation`、`current_assessment`、画面表示へ反映し、それより前のworker結果は破棄する。破棄した評価が連続実行のstepに属し、同じ実行世代がまだ有効な場合、`Application`は評価の連鎖を保てないため連続実行を`assessment_superseded`理由で停止する。

判断workerはprovider応答後に判断履歴JSONと判断trace JSONの一時ファイルを準備し、ファイル内容の生成中はRunControllerのlockを保持しない。workerは両方の一時ファイルを準備した後、RunControllerのlock内で開始世代を再検証し、履歴・traceとエンジンの前回判断状態を公開する。利用者が一時ファイル準備中にStopを押すと、RunControllerは直ちに世代を停止し、workerは未公開の一時ファイルを破棄する。最終的なファイル置換中だけStop処理はcommit完了を待ち、停止後に古い世代の履歴が新規commitされることを防ぐ。
