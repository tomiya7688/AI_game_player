# 画面キャプチャ

`WindowsScreenCapture` はWin32 APIで仮想デスクトップをBGRAフレームとして取得する。取得だけを責務とし、OCR・特徴量抽出・OS入力は行わない。Windows以外では明示的にエラーにする。

`ScreenFrame` は幅・高さ・生BGRAバイト列と取得時刻 `captured_at` を持つ。取得時刻はプロセス内で比較する `time.monotonic()` 秒で、実時間・日時ではない。`FrameAnalyzer.analyze()` は`ScreenFrame`を`ScreenObservation`へ変換する。

Win32/GDIのハンドル取得に失敗した場合は明示的なエラーにし、確保済みのDC・Bitmapは失敗経路でも解放する。API依存を注入して、この境界を実入力なしでテストできる。

`window_handle`指定時は対象HWNDを検証する。対象が可視・非最小化で、主画面内に収まり、Z-order上の他の可視ウィンドウにも覆われていないことを確認できた場合のみ、その画面領域を取得する。それ以外はタイムアウト付き`WM_PRINT`で対象アプリ自身に描画を要求し、別ウィンドウの画素を代用しない。描画要求に失敗・タイムアウトした場合は明示的なエラーにする。アプリや描画APIによっては最小化・非表示時やDirectX描画内容を返せない場合があり、取得内容の完全性はまだ保証しない。`window_handle`を省略した場合は従来どおりデスクトップ全体を取得する。

ウィンドウ一覧には可視状態によらずタイトル付きHWNDを含め、同一タイトルの複数ウィンドウもHWND表記で個別に選択できる。HWNDが取得中に失効した場合はフレームを返さず失敗する。

## Shared Frame Producerで1回のcaptureを複数consumerへ配る

実装者は`SharedFrameProducer`へ`capture() -> ScreenFrame`を持つbackendを渡すと、Producerのcapture threadが各capture完了後に指定秒数を待ち、同じ`FramePacket`を複数のconsumerへ配る。各packetはProducer内で単調増加する`frame_id`、capture source切替ごとに増加する`source_generation`、元の`ScreenFrame`を持つ。画面サイズは各`ScreenFrame.width`と`ScreenFrame.height`で確認でき、resize後のframeも同じstreamで受け取れる。

次の例はデスクトップを取得し、最新frameを1件まで保持するsubscriptionから1枚を読む。Windows以外で`WindowsScreenCapture`を使うとcaptureは失敗する。

```python
from ai_game_player.screen_capture import WindowsScreenCapture
from ai_game_player.shared_frame_producer import SharedFrameProducer

producer = SharedFrameProducer(WindowsScreenCapture(), interval_seconds=1 / 15)
latest_frames = producer.subscribe()
producer.start()
packet = latest_frames.get(timeout=1.0)
if packet is not None:
    print(packet.frame_id, packet.frame.width, packet.frame.height)
producer.stop(timeout=2.0)
```

各consumerは`subscribe()`で独立したbounded queueを登録する。`LATEST`は未読frameを新しいframeで置き換え、最新画面の解析に向く。`ORDERED`は指定数まで古いframeを保持し、queue満杯時は新しいframeを破棄するため、producerは遅いconsumerを待たない。各subscriptionとProducerの`metrics`は破棄frame数を公開する。

実装者は`replace_source()`で選択windowなどのbackendを切り替える。切替時に未読の旧source frameを破棄し、進行中の旧source captureが後から返った場合も配送しない。consumerは`source_generation`でsource境界を識別する。Producerは幅・高さが正でBGRA byte数が寸法に一致するframeだけを配信し、capture時刻が有限かつ前frame時刻以上であることを検証する。旧sourceのcapture中にsourceが切り替わった場合、旧sourceが返すエラーや不正frameを破棄して新sourceのcaptureを続ける。現在のsourceが不正frameまたはbackend例外を返した場合はcaptureを停止し、全consumerの`get()`へ`FrameProducerError`として通知する。この失敗で未読queueを破棄した数もProducer metricsに加える。`stop(timeout)`はcapture threadの停止を要求する。停止要求は取り消せないため、`timeout`内にbackendの`capture()`が戻らず`False`を返した後も、Producerは新しいsubscriptionとsource切替を拒否する。`get(timeout)`は指定時間内にframeがなければ`None`を返し、正常停止後にqueueが空でも`None`を返すため、consumerは`is_closed`でtimeoutと終了を区別する。
