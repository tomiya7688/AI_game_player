# 設定と履歴の永続化

`ConfigStore` はProvider、モデル、Endpoint、人格、目的を `config.json` に保存する。未作成時は安全なローカル規則設定を返し、未知の設定キーは無視する。

`ExecutionHistory`と`HistoryStore`は、旧JSON形式の履歴をSession Event Journalへ接続する`LegacyEventAdapter`を受け取ります。adapterを設定した場合、両クラスは旧JSONファイルを上書きせずSession Event Journalへ保存します。adapterを設定しない場合、両クラスはJSONファイルを直接読み書きします。`KnowledgeStore`はゲーム知識をJSON配列へ保存します。

JSON配列を使う保存経路は、保存先と同じディレクトリに一時ファイルを作り、JSONを書き込みます。保存処理はPythonのファイルバッファを`flush`し、OSに`fsync`で内容の同期を要求してからファイルを置換します。adapterを設定しない`HistoryStore.prepare_append()`は一時JSONを準備し、呼び出し側が`publish()`を実行した時点で置換します。adapterを設定しない`ExecutionHistory.append()`と`KnowledgeStore.add()`は、一時ファイルを準備した後に置換します。書込・同期・置換に失敗した場合、既存のJSONファイルを保持し、一時ファイルの削除を試みます。

既存ファイルのJSON構文が不正な場合やトップレベルが配列でない場合、各保存経路は追記前にエラーを返し、ファイルを上書きしません。`ExecutionHistory`は配列要素がobjectでない場合も拒否します。原子的置換は書込中断で部分的なJSONが保存先に現れることを防ぎますが、複数プロセスによる同時追記を直列化しません。
